# EV-FinAgent

基于大语言模型的新能源车企经营研判与风险预警助手。面向银行总行产业金融、公司金融和供应链金融的贷前初筛场景：客户经理上传新能源车企年报后，快速获得“经营质量如何、在三家样本中处于什么位置、哪些风险情景可能触发、风险如何传导、应持续监控什么、原文在哪一页”。

> 当前 MVP 仅支持小鹏汽车、理想汽车和蔚来汽车。输出用于经营风险辅助分析，不构成授信审批结论。

## 1. 项目背景

银行为新能源车企提供流动资金贷款、综合授信或供应链金融服务时，需要理解企业的增长质量、盈利能力、研发投入强度、现金消耗与偿债缓冲。新能源车行业同时具有高研发投入、价格竞争激烈、供应链复杂和资本开支较大的特点，仅看营收增速不足以判断风险。

年报通常长达数百页，三家企业的语言、币种单位和披露位置又不完全一致。人工查找营收、交付量、毛利率、研发费用、现金储备和经营现金流耗时较长，且分析结论不容易回溯到原文。

本项目选择一个小而具体的切入点：**年报经营指标抽取与经营风险初筛**。它不替代银行的信用评级、担保审查和审批流程，只为客户经理形成有引用依据的第一版分析底稿。

## 2. 业务问题与边界

系统回答四个问题：

1. 年报披露了哪些关键经营指标？
2. 企业现金覆盖、研发压力、现金流质量和毛利水平如何？
3. 风险判断由哪些确定性指标触发？
4. 每一个基础数据能否回到 PDF 的具体页码和原句？
5. 利润、现金流、毛利和研发投入组合起来反映了什么经营状态？
6. 企业在小鹏、理想、蔚来三家同年样本中处于什么位置？
7. 当前指标组合可能触发哪些风险情景，银行应该监控什么？

MVP 不做股票预测、高频交易、复杂量化模型或大型多 Agent 编排；不使用 LLM 直接做除法或评分；不把 AI 输出当成最终授信结论。

## 3. AI 解决方案与架构

```text
年度报告 PDF
      │
      ▼
PyMuPDF 按页解析 ──► PageText(page, text)
      ├──────────────────────────────┐
      ▼                              ▼
带页码全文输入LLM                 指标候选页检索
      ▼                              ▼
开放式自然语言经营分析           JSON结构化指标抽取
      ▼                              ▼
自动分句 + 中英文检索词扩展       页码与原句反校验
      ▼                              ▼
动态BM25召回相关页面              Python单位归一与计算
      ▼                              ▼
原分析语句 + 召回页面二次核验     规则评分与同业比较
      └──────────────┬───────────────┘
                     ▼
证据约束后的自然语言报告 + 逐句审计轨迹
      │
      ▼

      │
      ▼

      │
      ▼

```

### LLM + Deterministic Computing

| 环节 | 责任主体 | 原因 |
|---|---|---|
| 语义理解、跨格式字段抽取 | LLM | 披露方式不统一，需要语言理解 |
| 全文开放式分析 | LLM | 避免固定字段限制模型发现未知问题 |
| 原子主张识别 | LLM + Python | 分离事实、计算、推论、定性表达和尽调问题；按金融重要性选择审核目标 |
| 中英文检索词扩展 | LLM | 将中文判断映射到英文年报披露术语 |
| 动态证据召回 | Python / BM25 | 为每条自然语言判断寻找高相关页面 |
| 证据复核与可信改写 | LLM + Python | LLM判断语义关系，Python逐字验证引文 |
| 原文候选召回 | Python | 降低上下文长度、成本和噪声 |
| 引用真实性校验 | Python | 不能仅相信模型自报页码 |
| 单位换算、比率、趋势 | Python | 结果需要可复现、可测试 |
| 经营质量五维评分、同业排名 | Python | 排名和权重需要透明、可复核 |
| 风险评分 | Python 透明规则 | 便于银行审计与解释 |
| 风险事件触发与传导链 | Python 规则 | 防止模型凭空预测风险事件 |
| 综合经营研判 | LLM | 把多维证据转为客户经理可读的分析判断 |

### 抽取字段

```json
{
  "company": "小鹏汽车",
  "year": "2024",
  "metrics": [
    {
      "metric": "vehicle_margin",
      "value": "18.1%",
      "source_page": 87,
      "source_text": "Vehicle margin was 18.1% for the year...",
      "verified": true
    }
  ]
}
```

系统固定抽取 8 个核心指标：`revenue`、`vehicle_delivery`、`vehicle_margin`、`gross_margin`、`rd_expense`、`cash_balance`、`operating_cash_flow` 和 `net_loss`。同时抽取 4 个仅供计算使用的支持字段：`gross_profit`、`total_cost_of_sales`、`vehicle_revenue` 和 `vehicle_cost_of_sales`。缺失或引用未通过反校验的字段返回 `null`。

如果年报未直接披露毛利率，但已披露并成功校验计算所需的基础字段，系统会由 Python 补算并明确标记为“计算值”，不会伪装成年报原文披露值：

- 综合毛利率 = 毛利润 / 营业收入
- 车辆毛利率 =（车辆销售收入 - 车辆销售成本绝对值）/ 车辆销售收入

综合毛利率计算还会使用“营业收入 - 销售成本绝对值 = 毛利润”做一致性校验；误差超过 0.5% 时拒绝计算。计算结果会保留公式、输入值、输入字段校验状态和来源页码。

### 金融计算

- 现金覆盖能力 = 现金储备 / 年度亏损绝对值
- 研发投入强度 = 研发费用 / 营收
- 经营现金流率 = 经营现金流 / 营收
- 净利润率 =（-净损益字段）/ 营收
- 盈利改善 = 本期毛利率 - 上期毛利率（计算层已支持；UI MVP 默认分析单份年报）

金额统一为人民币百万元、百分比统一为小数、交付量统一为辆。风险分数越高表示经营风险越高；经营质量分越高表示经营质量越强。评分 V2 显式评价净利润率，亏损企业的现金覆盖只作为缓释项，不能抵消亏损本身。规则位于 `risk_analyzer.py` 和 `business_analyzer.py`，每个结论都返回触发依据；这是一套用于项目演示的专家规则，不是银行生产信用评级模型。

### 经营研判与事件预警

经营质量由盈利质量、现金流质量、流动性缓冲、样本同业位置和研发投入可持续性五个维度组成。内置的 2025 同业基准来自本项目对三份上传年报的已校验抽取，比较营收、交付、综合毛利率、汽车毛利率、净利润率、经营现金流率和现金储备。

事件预警不是预测某个事件必然发生，而是将异常财务组合转化为银行可监控的风险情景。例如：

```text
净利润为正 + 经营现金流为负
        ↓
利润现金化风险
        ↓
营运资金占用上升 → 现金缓冲下降 → 短期融资需求增加
        ↓
监控应收、存货、合同负债、应付和季度经营现金流
```

每个预警包含触发依据、预警等级、传导路径、持续监控指标和银行核验动作。LLM 只能综合已经由 Python 触发的事件，不能自行增加外部事实。

## 4. 技术亮点

- **LLM Structured Extraction**：通过严格 JSON Schema 约束字段、类型和数量，温度设为 0。
- **Analysis-first RAG**：第一阶段阅读全文并分别输出分析正文、原子主张与尽调问题；随后按金融重要性召回证据、逐条复核，并只使用已验证事实重新合成报告。
- **全文覆盖可观测**：记录实际输入页数、字符数和截断状态；超过安全上限时明确失败，不静默丢弃尾部页面。
- **原子主张审计**：数字、趋势、重大金融风险和强推论强制审核；不再按位置等间隔抽样。每条主张标记为证据支持、部分支持、证据不足、存在矛盾或不可由年报核验。
- **结论与尽调分离**：单份年报无法回答的问题只进入“补充尽调事项”，不会混入主体经营结论。
- **事实—推论双通道**：先逐字核验事实，再由LLM组合至少两个已验证事实生成经营推论；第二个复核阶段检查因果偷换、过度外推和适用边界，只有通过或弱化后的推论进入最终报告。
- **抗幻觉与数据溯源**：模型必须返回页码和逐字原句；程序在对应页面反向查找，失败即置空。
- **直接披露与推导值分离**：8 个核心指标与 4 个支持字段分别管理；毛利率缺失时仅用已校验字段确定性补算，并在界面和 TXT 报告中标明来源类型。
- **确定性金融计算**：单位换算、比率和评分全部由 Python 完成，LLM 不参与算术。
- **可解释风险分析**：评分由现金覆盖、经营现金流、毛利率、趋势和研发压力等透明规则组成。
- **经营质量诊断**：用五维得分解释企业为什么“看起来好或不好”，同时保留每个维度的权重。
- **同业位置**：基于三家公司同年度已校验数据计算排名、中位数和样本分位，明确限定为样本比较而非全行业排名。
- **事件预警**：从财务信号组合推导风险传导链、监控指标和贷前/贷后动作，避免泛泛罗列风险。
- **工程落地**：模块化代码、环境变量配置、OpenAI 兼容接口、Streamlit UI、会话内多公司比较和 pytest 测试。
- **AI 辅助决策而非 AI 替代决策**：报告只提供贷前核验建议，并明确声明不构成授信结论。

## 6. 如何运行

推荐 Python 3.11 或 3.12。

### 创建环境

Windows PowerShell：

```powershell
cd EV-FinAgent
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

macOS / Linux：

```bash
cd EV-FinAgent
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

### 配置兼容接口

```powershell
$env:OPENAI_API_KEY="your-api-key"
$env:OPENAI_BASE_URL="https://api.openai.com/v1"
$env:OPENAI_MODEL="gpt-4o-mini"
```

`OPENAI_BASE_URL` 可替换成支持 Chat Completions 与 `json_schema` response format 的 OpenAI 兼容服务。若供应商只支持旧式 JSON mode，需要调整 `extractor.py` 和 `report_generator.py`；仅声称“兼容 OpenAI”不代表一定支持严格 Structured Outputs。

### 使用 DeepSeek API

页面左侧选择 `DeepSeek` 后，系统会自动填写：

```text
Base URL: https://api.deepseek.com
Model: deepseek-v4-flash
```

直接粘贴 DeepSeek API Key 即可。也可以使用环境变量：

```powershell
$env:DEEPSEEK_API_KEY="your-deepseek-api-key"
$env:DEEPSEEK_BASE_URL="https://api.deepseek.com"
$env:DEEPSEEK_MODEL="deepseek-v4-flash"
```

DeepSeek 当前使用 `json_object` JSON Output，而非 OpenAI 的严格 `json_schema` Structured Outputs。因此项目会额外执行固定字段白名单、类型检查、指标补齐、页码原句反校验和失败重试；无法验证的基础指标仍会被置为 `null`。

对于结构化抽取和结构化报告，项目会显式关闭 DeepSeek 思考模式，把输出 token 预算留给 JSON 内容，降低空响应与 JSON 截断概率。横向比较等自由文本任务仍使用服务默认能力。

### 启动与测试

```powershell
python -m pytest -q
python -m streamlit run app.py
```

浏览器打开 Streamlit 地址后：上传 PDF → 选择公司和年度 → 点击“开始分析”。依次分析多家公司后，在“公司比较”页查看横向表格和 AI 解释。

页面提供分析草稿、证据审计、经营指标、经营研判、事件预警、风险评分、AI综合报告、过程监督、来源引用、完整报告和公司比较十一个审阅视图。分析草稿与补充尽调事项分开显示；“证据审计”展示修订动作、五类核验结果、RAG召回页和逐字校验后的引文。

每次分析完成后会自动生成 UTF-8 TXT 完整报告，并保存到项目父目录的 `outputs` 文件夹；也可以在“完整报告”页面直接预览和下载。报告附带第一阶段开放分析、证据约束后的可信版本、逐句判定、召回页和已校验原文，使用户能看到模型最初说了什么、哪些内容得到支持、哪些内容被修正。

### 年报选择注意事项

- 优先使用公司官网或交易所发布的正式年度报告，并人工确认报告年度。
- 当前版本依赖 PDF 文本层；扫描版 PDF 需要先做 OCR。
- 页码指 PDF 文件页序（从 1 开始），可能与印刷页脚编号不同。
- 横向比较应选择同一报告期、相同会计口径的数据。
- 不要把包含客户隐私或未公开授信材料的文件发送到未经银行批准的外部模型服务。

## 7. 一个月内的实施计划

| 周次 | 交付内容 | 验收标准 |
|---|---|---|
| 第 1 周 | PDF 解析、页码切块、三家公司指标字典 | 能定位 8 个核心指标及 4 个支持字段的候选页 |
| 第 2 周 | Structured Outputs、引用反校验、单位归一 | 缺失值不编造，引用可回查 |
| 第 3 周 | 金融计算、风险规则、比较与测试 | 算术可复现，规则有解释 |
| 第 4 周 | Streamlit、案例评测、README 与演示 | 三份年报完整跑通，录制演示 |

建议额外制作一个小型评测集：对三家公司各选 1–2 个年度，人工标注 8 个核心指标、4 个支持字段及页码，统计字段准确率、引用命中率、计算一致性、空值正确率、单份报告耗时和模型成本。面试中，这比单纯展示页面更能体现生产意识。

## 9. 简历写法

项目名称建议写为：**EV-FinAgent｜新能源车企年报经营风险分析助手（个人项目）**。

可直接使用的项目描述：

> 面向银行新能源车产业金融贷前初筛场景，独立设计并实现 Analysis-first RAG 年报审计助手：先将带页码全文交给 LLM 生成不受固定字段限制的开放式经营分析，再自动拆分自然语言判断、扩展中英文财务检索词并使用 BM25 回查相关页面；将原始判断与召回证据交由第二阶段模型复核，按支持、部分支持、矛盾、证据不足和不可核验五类输出可信改写，并由 Python 对所有保留引文逐字反校验；同时保留结构化指标、确定性计算、同业比较和风险规则通道，在 Streamlit 中展示从原始分析到最终结论的完整审计轨迹。

如果完成真实评测，再将可验证数字补入简历，例如：

> 在人工标注的 6 份年报、48 个指标测试集上，实现字段准确率 XX%、引用命中率 XX%，单份报告平均分析耗时由人工约 XX 分钟降至 XX 分钟。

不要填写尚未测量的准确率或效率数据。面试时重点讲清三个取舍：为什么只做三家公司、为什么 LLM 不负责计算、为什么模型给出的引用仍需程序反校验。这三个决定最能体现银行金融科技岗位需要的业务边界、可审计性与工程风险意识。

## 10. 已知限制

- 关键词召回是轻量 MVP，在复杂表格或跨页语句上可能漏召回。
- 年报单位识别依赖文本上下文，极端表格格式需要更强的表格解析。
- 规则阈值是演示性专家规则，尚未使用银行历史违约样本校准。
- 仅分析公开年报，不能覆盖征信、担保、集团关联、舆情和实时供应链风险。
